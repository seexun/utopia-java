# P1 后端业务迁移实现计划（jknow 迁移 · 阶段二）

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 把 utopia-java 的 7 个域模块 + utopia-server 全量业务迁入 jknow（Boot 4.1.2 宿主），认证重宿主到若依（含 personal token 双通），Flyway 全链 V0000→V0101，全量业务 API 冒烟绿。

**架构：** 模块按依赖序搬运（common/llm → reason/ingest/extract → store → search → contract → server）；server 除 auth/oidc 外整体落位 `jknow-admin` 的 `tech.seexun.jknow.web.knowledge.*`；用户身份桥接用 `sys_user.utopia_uuid` 列（业务侧 UUID 形状不变），ClientContext 由若依 LoginUser 桥接填充；personal token（`pt-` 前缀）走独立验签 filter 与若依 JWT 双通。

**技术栈：** Java 21 / Spring Boot 4.1.2 / MyBatis 4.x / jjwt 0.13 / Jena 5.3 / JSqlParser 5.4 / Flyway（Boot 托管）/ Testcontainers 2.x / pgvector PG16 / ES 8.14.3+IK（条件依赖）/ LLM API（条件依赖）。

```java
package tech.seexun.jknow.web.knowledge.auth;

import jakarta.servlet.FilterChain;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.web.filter.OncePerRequestFilter;
import tech.seexun.jknow.common.core.domain.model.LoginUser;

/**
 * 身份桥接：若依 LoginUser → 业务 ClientContext（uuid 形状不变，方案 B）。
 * order 在若依鉴权之后（SecurityConfig filterChain 末尾 addFilterAfter 或 @Order 兜底）。
 */
public class ClientContextBridgeFilter extends OncePerRequestFilter {
    private final UtopiaUuidResolver resolver; // Long userId -> sys_user.utopia_uuid（带 Caffeine/ConcurrentMap 缓存）

    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain)
            throws java.io.IOException, jakarta.servlet.ServletException {
        Authentication auth = SecurityContextHolder.getContext().getAuthentication();
        if (auth != null && auth.getPrincipal() instanceof LoginUser lu) {
            req.setAttribute(ClientContext.ATTR, new ClientContext(resolver.uuidOf(lu.getUserId()), lu.getUsername()));
        }
        chain.doFilter(req, res);
    }
}
```

`UtopiaUuidResolver`：jknow-admin 内新组件，直查 `select utopia_uuid from sys_user where user_id=?`（jdbcTemplate，ConcurrentHashMap 缓存；sys_user 更新极少，无失效需求，YAGNI）。**注意**：若 ClientContext 原装配 API 不是 `setAttribute(ATTR, ...)` 形态，以源码实况为准适配（先读源 ClientContext/SessionFilter 再写，保持 20 处业务引用零改动）。

```bash
#!/usr/bin/env bash
# P1 业务冒烟：若依登录→业务造数→各域走查→pt- 双通。前置：应用 19080、compose pg/redis。
set -euo pipefail
cd "$(dirname "$0")/.."
BASE=${JKNOW_APP_BASE:-http://localhost:19080}
# 复用 p0 的自动关验证码三步（psql update + flushdb）
psql_update() { docker compose -f docker-compose.dev.yml exec -T pg psql -U postgres -d jknow -c "$1"; }
psql_update "update sys_config set config_value='false' where config_key='sys.account.captchaEnabled'"
docker compose -f docker-compose.dev.yml exec redis redis-cli flushdb >/dev/null
TOKEN=$(curl -s --max-time 10 -X POST "$BASE/login" -H 'Content-Type: application/json' -d '{"username":"admin","password":"admin123"}' | sed -n 's/.*"token":"\([^"]*\)".*/\1/p')
[ -n "$TOKEN" ] || { echo "FAIL: login"; exit 1; }
AUTH="Authorization: Bearer $TOKEN"
J='Content-Type: application/json'
# 造数
WS=$(curl -s --max-time 10 -X POST -H "$AUTH" -H "$J" -d '{"name":"p1-smoke"}' "$BASE/api/v1/workspaces" | sed -n 's/.*"id":"\([^"]*\)".*/\1/p')
KB=$(curl -s --max-time 10 -X POST -H "$AUTH" -H "$J" -d '{"name":"p1-smoke-kb"}' "$BASE/api/v1/workspaces/$WS/kbs" | sed -n 's/.*"id":"\([^"]*\)".*/\1/p')
# 只读断言（响应字段名以实况为准微调，断言 HTTP 200 而非业务字段）
for ep in "api/v1/workspaces" "api/v1/kbs/$KB/graph" "api/v1/kbs/$KB/ontology" "api/v1/kbs/$KB/documents" "api/v1/kbs/$KB/relations"; do
  CODE=$(curl -s --max-time 10 -o /dev/null -w '%{http_code}' -H "$AUTH" "$BASE/$ep")
  [ "$CODE" = 200 ] && echo "PASS: $ep" || { echo "FAIL: $ep code=$CODE"; exit 1; }
done
# pt- 双通（路径从 TokensController 实提）
# ES 条件断言：curl -s localhost:9200 通则打检索接口，否则 echo "SKIP: es"
# LLM 条件断言：env JKNOW_LLM_API_KEY 非空则打对话接口，否则 echo "SKIP: llm"
echo "ALL PASS"
```
